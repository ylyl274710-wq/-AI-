# 知识库维护指南

> 回答一个问题：**怎么往资料库里加知识？**
> 当前（2026-09-27）知识库没有管理后台，添加走「种子数据文件 + 幂等导入」，
> 全程可版本管理、可评审、可回滚 —— 对面试项目这是优点，对日常运营是待办
> （管理 API + 审核流见文末「尚未实现」）。

## 一、添加新条目（最常用）

**第 1 步：在 `backend/app/seed/knowledge_data_ext.py` 里追加条目。**

病害/虫害条目用文件里的 `_d()` 构建器，它保证「结构化发生条件」与
「给农户看的正文」永不脱节（正文的发生条件段落由 conditions 自动渲染）：

```python
_d(standard_name="番茄新增病害名",           # ★ 唯一键，与已有条目不得重名
   aliases=["俗称1", "俗称2"],              # 别名：检索时经 crop_aliases/口语映射生效
   category="disease",                      # disease / pest / physiological
   crop_names=["番茄"],                     # 多对多；跨作物害虫可列多个
   pathogen="病原学名",                     # 虫害传 ""（空串）
   severity="high",                         # high / medium / low
   symptoms="症状描述……",                   # 要写清「与哪个病怎么区分」
   conditions={"temp_min": 18, "temp_max": 24, "humidity_min": 85,
               "rain_hours_min": 4},        # 结构化发生条件（见下）
   stage_susceptibility={"苗期": "中", "结果期": "高"},
   control_advice="防治思路……",             # 只写思路与药剂类别，不写商品名剂量
   differentiate="与 XX 的区分：……",        # 可选，检索与鉴别的关键内容
   occurrence="传播途径等补充。")            # 可选
```

**conditions 字段含义（风险计算的唯一事实来源，必须填真实数值）：**

| 字段 | 含义 | 用在哪 |
|---|---|---|
| temp_min / temp_max | 适宜发病的平均气温区间（℃） | `/weather/risk` 打分 + 正文渲染 |
| humidity_min | 最低相对湿度（%） | 同上 |
| rain_hours_min | 连续降雨累计小时阈值 | 同上 |
| wind_max | 风速上限（m/s） | 同上 |
| duration_days | 持续天数（展示用） | 正文 |

没有天气关联的条目（如土传病害）conditions 传 `{}` 或只填温度；
生理性缺素条目参照已有的「辣椒脐腐病」写法。

通用知识（不针对某个病害）加到同文件的 `GENERAL_KNOWLEDGE_EXT`，
格式参照「叶片发黄的常见原因」条目：title / category / tags / content，
content 用 `## 小节标题` 分节 —— 索引器会按标题切块，每节独立可检索。

## 二、导入与生效

```bash
cd backend
../.venv/Scripts/python.exe -m app.seed.runner
```

- **幂等**：按 standard_name / title 去重，重复执行不会产生重复数据；
- 新条目自动创建对应的 `DiseaseRecord` + 知识文档，并重建向量索引；
- 想更新已有条目的正文？在 `knowledge_data_ext.py` 的 `UPGRADED_DOCS`
  里按标题放新内容 —— runner 检测到「库里的明显短于新版（>20%）」会
  自动升级并重建该文档的索引；
- `review_status` 统一置 approved 仅供演示；正式使用前应逐条补文献出处
  （`knowledge_sources` 表 + `/api/v1/knowledge/sources` 可查）。

## 三、加完之后必做：跑检索评测

```bash
.venv/Scripts/python.exe backend/scripts/check_retrieval.py
.venv/Scripts/python.exe backend/scripts/check_chunker.py
.venv/Scripts/python.exe backend/scripts/smoke_http.py
```

**为什么必做**：语料扩大会改变检索排序（2026-09-26 实测：条目 30→101 时
hit@1 一度从 72% 掉到 61%，靠别名映射 + 标题命中 + 语料增厚拉回 69%/97%）。
评测集（36 条口语提问）就是防止「加了知识反而答变差」的尺子；
新增条目如果覆盖了新的典型问法，顺手往评测集里加一条用例。

## 四、注意事项

1. **standard_name 是全系统的连接键**：识别候选、天气风险、引用来源都按它
   关联。改名等于断链，只加不改。
2. **正文别手写发生条件的数字**：数字只在 conditions 里写一份，正文自动渲染。
3. **别在 control_advice 里写具体商品名和剂量**：用药由规则引擎按登记数据
   校验后放行，条目里写死会绕过这道闸。
4. **每条都该有 differentiate**：「和什么病怎么区分」既是检索命中的关键词，
   也是农户最需要的内容（评测集里多条用例靠它命中）。
