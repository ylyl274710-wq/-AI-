## 一、接口直接报错类（改动即崩，最容易发现）

| # | 问题 | 根因 | 修复 | 防线 |
|---|---|---|---|---|
| D1 | 三张表按 `deleted_at` 过滤但模型没有该列 → AttributeError | 代码按设计意图写了过滤，迁移没跟上 | 加列 + 迁移 | 软删除对农事记录有真实价值（复盘依据），不删过滤 |

这一类的共同点：**测试全绿、用户看到的是错误答案**。

## 方法论提炼（比单个 bug 更值钱的部分）

1. **降级必须可见**——降级可以，但要 `is_mock`/`caveat`/`storage` 字段告诉用户；
   兜底可以宽，但兜底必须说话（裸 except 曾把漏写的 import 吞成「探测失败」）。
2. **假数据比没有数据更糟**——mock 混进真窗口、模型知识混进知识库回答，都不允许。
3. **先建尺子再动刀**——检索评测集（hit rate）、切块器不变量、负向自测；
   「一个永远通过的检查器等于没有检查器」。
4. **断言落在不变量上**，不落在当前环境值上（同一错误踩了 3 次后固化成规矩：
   修完一处，全项目搜同类写法）。
5. **静默失效是最危险的家族**——不报错只是不对。防线是「从入口到落库的全链路
   留痕 + 体检端点 + 真实浏览器层」。
6. **配置项存在 ≠ 实现存在**——凡是「开关一开就换代码路径」的地方，必须有
   「用真实配置真跑一次」的验证（D27/D30/D31 同一条教训）。
7. **同一文件的多个 Edit 必须串行**——不报错、只丢改动（踩了 3 次）。
8. **测量方式先于结论**——弹窗问题换了两版探针才找到「枚举可见控制台窗口」
   这个不需要假设的指标；「无法确证」也是一个需要证据的结论。
9. **假红与真红处理方式相反**——先诊断分清（GBK curl、并发 sleep），再动手。
10. **给固定管线加节点，必须同步审查路由兜底**——D33 的工具循环被静默跳过，
    无任何报错，靠读 SSE 轨迹发现。
