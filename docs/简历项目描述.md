## A 版 · 简历用（贴简历项目栏）

**农业病虫害智能诊断与农事决策 Agent**（个人独立开发）

技术栈：Python / FastAPI / PostgreSQL(pgvector) / Function Calling / RAG / ONNX / SSE / Vue 可迁移零依赖前端

- 独立设计并实现面向农户的病虫害诊断系统：自研 9 节点 Agent 状态机（意图识别→多模态诊断→RAG 检索→规则校验→流式生成），并按问题性质实现**双形态 Agent**——诊断走确定性管线、开放咨询走 Function calling 工具循环（LLM 自主调用知识库/天气/地块 3 类工具）。
- 构建**评测驱动的混合检索**：pgvector 向量 + BM25 + 标题命中三路 RRF 融合，标题感知切块与别名归一化；建立 36 条口语化评测集驱动迭代，检索命中率 hit@3 由 81% 提升至 **97%**（hit@1 69%）。
- 实现**本地专用模型 + 通用 VLM 双通道识别**：在本地 GPU 完成 PlantVillage 39 类病害分类模型训练（验证集准确率 99.89%，ONNX 推理 <100ms），分类器输出可复现概率并与 VLM 候选合并、参与置信度判定，规避纯 VLM 的不可校准问题。
- 设计**可计算置信度闸门与用药合规引擎**：置信度由 margin/agreement/coverage 三个可复算分量加权（非模型自报），低于阈值不给出诊断而转补拍引导；31 个登记产品按作物/防治对象/生长阶段/安全间隔期四维校验，剂量一律引用标签原文，杜绝 LLM 编造用药剂量。
- 落地**生产级可靠性**：SSE token 级流式、多轮会话记忆、天气/存储/LLM/分类器四链路分级降级且状态对用户可见；建立 82 项端到端冒烟、53 项单元测试、30 项真实浏览器 e2e 的回归体系，全部绿。

## B 版 · 详述（个人网站 / GitHub / 面试展开）

### 项目背景与约束

面向农户的病虫害诊断场景有两个强约束：**错误代价极高**（用错药）且**用户无法自我纠错**（农户不具备植保知识）。因此整个系统的设计主线是「不确定就不给结论」：识别置信、证据充分才给用药建议，否则明确要求补充信息。

### 核心工作

**1. Agent 架构：按问题性质选择形态**
- 自研 9 节点有限状态机承载诊断主链路，节点级工具白名单（越权调用拒绝并落痕），全程轨迹/工具调用/引用来源落库，事后可复盘"哪一步查了什么、为什么给出这个结论"。
- 开放咨询走 Function calling 工具循环：LLM 自主决定调用知识库检索 / 天气风险 / 农场地块工具（最多 3 轮），循环只收集证据，最终回答仍经统一的流式生成 + 输出护栏，两条路径共享出口纪律。
- 踩坑与修复：为管线新增节点时路由兜底逻辑沿主链查找导致新节点被静默跳过（无任何报错），靠 SSE 轨迹排查定位；工具结果序列化需在协议边界处理非 JSON 类型；模型会"自信跳过"工具，故代码层保证关键证据源强制可达。

**2. 检索：评测驱动的混合 RAG**
- 三级切块策略：Markdown 标题分节 → 段落/句子贪心合并（size 420 字，节标题冗余入块、长度预算制）；短文档整篇成块不硬切。
- 三路 RRF 融合（向量 / BM25 / 标题命中），只用排名不引入跨量纲加权；别名归一化（西红柿→番茄）打通口语输入的作物过滤。
- 以 36 条口语化评测集为回归防线驱动四轮迭代（别名映射 → 标题命中 → 语料扩充 3 倍 → 文档增厚机制），hit@3 81%→97%；每轮均验证无负向影响后才合入。

**3. 多模态：本地专用模型 + VLM 双通道**
- 使用 PlantVillage 公开数据集（39 类、5.5 万张）在本地 GPU 训练 ResNet18（AMP 混合精度），导出 ONNX 由后端 CPU 推理；逐类准确率报告决定哪些类别可信。
- 与 Qwen3-VL 组成双通道：分类器输出可复现的 top-k 概率并置顶参与结论解析，VLM 负责解释与建议；未映射类别诚实不输出，不冒充诊断。
- 实测确认温室图与真实实拍的 domain gap（实拍图分类器失效），系统自动降级为 VLM 主导——识别置信与实拍局限都对用户透明。

**4. 置信度与用药合规**
- 置信度 = margin（候选区分度，RRF 理论最高分归一化）+ agreement（多图/多通道一致性，分类器作为可复现观察者参与投票）+ coverage（证据覆盖度）三分量加权，全部可复算、可消融。
- 用药规则引擎按农药登记信息四维校验（作物/防治对象/生长阶段/安全间隔期），33 个登记产品覆盖 80/101 种病虫害；剂量一律引用标签原文，全拦时区分"无登记"与"阶段不符"并给出精准提示。
- 输出护栏对 LLM 生成文本同样生效：命中拦截规则的剂量句会被剔除。

**5. 可靠性与工程化**
- 四条外部依赖（LLM/天气/对象存储/分类器）均有分级降级路径，降级状态通过 health 端点与界面提示对用户可见。
- SSE token 级流式（单次回答 300+ delta 事件）；多轮会话记忆落库并回灌提示词。
- 质量体系：82 项端到端冒烟、53 项单元测试（含物理不变量断言）、30 项真实浏览器 e2e、各组件接线自检；静态资源 no-cache、前端资源版本耦合治理。
- 基础设施脚本化：PostgreSQL/Redis/MinIO/后端统一托管，看门狗退避熔断、单实例锁、启动自检（曾定位并修复进程互杀、控制台弹窗两个环境级疑难）。

## 使用提醒（不是简历内容，是给你的）

1. **数字必须能自证**：简历上每一个数字都对应仓库里的评测脚本，面试官若要求现场跑，`docs/问题与解决总结.md` 有全部出处；
2. **主动声明边界**：数据由 LLM 辅助整理并标注来源分级、识别模型存在实拍 domain gap、单机未做压测——主动讲边界是这类岗位的加分项；
3. **若岗位强调前端**：说明零依赖前端是面向农户"双击即用"的刻意选择，且 e2e/契约检查体系完整，强调可快速迁移 Vue/React；
4. **放在简历最前的关键词**（ ATS 友好）：LLM Agent、Function Calling、RAG、pgvector、多模态、SSE、Prompt Engineering、评测体系、FastAPI、ONNX。
